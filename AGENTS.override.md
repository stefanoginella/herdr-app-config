# This Herdr setup

This folder is the Herdr app's home and also a git repository of the owner's customizations.

**Read `AGENTS.md` in this folder in full before changing anything, unless it is already in your context.** It is Herdr's manual for the installed version. Herdr rewrites it on every start, so never edit it: notes about this setup belong in this file and in `docs/agents/`.

Why this file has this name: Codex reads one instruction file per folder and prefers `AGENTS.override.md`, so it gets these notes and the pointer above. Claude Code gets both files through the imports in `CLAUDE.md`.

## What is custom

Everything not listed here is Herdr's and is replaced on every start.

**Before changing a mod, or saying how it works, read its notes in full.** They are not loaded with this file. Each says what the mod is, what each of its files does, where its state lives, how to try it, and the behavior to preserve: what must keep working, why it is built the way it is, and what was and was not tried by hand.

| Mod (`mods/<name>/`) | What it is | Notes |
|---|---|---|
| `space-folders` | A clone of Herdr's `spaces` sidebar (from version 0.1.18) with one level of named, foldable folders of spaces, and each space's containers (DDEV, Docker Compose) and agents | `docs/agents/space-folders.md` |
| `agents-unread` | A clone of Herdr's `agents` list (from version 0.1.18) where an idle agent can be marked unread | `docs/agents/agents-unread.md` |
| `files-actions` | A clone of Herdr's `files` panel (from version 0.1.18) without its preview, with file type icons, a right-click menu, drag to move, drops from Finder and undo | `docs/agents/files-actions.md` |
| `file-editor` | A text editor that opens as a pane beside the terminals. Not a clone | `docs/agents/file-editor.md` |
| `editor-links` | A link handler: Cmd-click on a file path in a terminal opens it in `file-editor`. Not a clone | `docs/agents/editor-links.md` |
| `project-search` | Search and replace in every file of the project, in a panel beside Files and Changes. Not a clone | `docs/agents/project-search.md` |
| `go-to-file` | Go to a file of the project by its name, in a popup. Not a clone | `docs/agents/go-to-file.md` |
| `git-panel` | The Git panel, in the place of Herdr's `changes`. Not a clone | `docs/agents/git-panel.md` |
| `git-diff` | The diff pane beside the terminals, opened by the Git panel. Not a clone | `docs/agents/git-diff.md` |
| `usage` | The dialog and sidebar widget of the AI agents' limits and usage. Not a clone | `docs/agents/usage.md` |

- **Hide names** is a mode of the whole window, not one mod: `space-folders`, `agents-unread`, `usage` and the three clones above draw made-up names while shared `names.hidden` is set. Read `docs/agents/hide-names.md` before changing where any of them draws a name.
- **Files kept the same in several mods**, since a mod imports only from its own folder: `alias.js` (in `status-names`, `tabs-names`, `pane-names`, `space-folders`, `agents-unread` and `usage`), `fieldkeys.js` (in `file-editor`, `project-search` and `go-to-file`) and `remote.js` (in `file-editor` and `project-search`). Change every copy together.
- **Keep the notes true.** A change to what a mod does, to where its state lives or to something under its "Behavior to preserve" goes into its notes in the same change. A note about one mod goes in its file, not here; a new mod gets a file and a row in the table.
- **Layout `main-folders`** (`layouts/main-folders.json`): a clone of Herdr's `main` (from version 0.1.18). The differences: its `spaces` block shows the mod `space-folders`, its `agents` block shows the mod `agents-unread`, its `files` block shows the mod `files-actions` and its `changes` block shows the mod `git-panel` (the block keeps its id, so the tab bar's Changes button opens it); the panel's stack has a third child, `search`, which shows the mod `project-search`; the `work` column ends with `search-keys`, a block 0 px tall with a second copy of `project-search` that only takes a key; and its root has `link_handlers: ["editor-links"]` (Herdr added it when it first saw that mod). The sidebar has a block of its own between `brand` and `sidebar-lists`, `usage-side` (62 px, the mod `usage` with props `{ role: "side" }`). Its `tabs` block shows the mod `tabs-names`, the tab block's pane frame has the header `pane-names`, and its `status` block shows `status-names` (each block keeps its id): Herdr's own, with hide names (see `docs/agents/hide-names.md`). The status bar has no usage figures: they were taken out, since the widget shows them. Its look adds, since 0.1.18: a `veil` of 0.3 on the tab block's pane frame (the panes you're not in fade, mod panes too) and an `accent` hover color on the root's divider.

## Working here

- The window is live: an edit applies to the running app within a second. After every change run `herdr-app check mods/<name>` and `herdr-app status`, and look with `herdr-app shot`.
- Pointer drags and typing cannot be driven from a shell. Say so when a change to those paths was not tried by hand.
- A menu, a dialog or a request can be driven from a shell with a throwaway mod: `mod.json` `{ "place": "none", "overlay": { "width": 60, "height": 30 } }`, opened with `herdr-app do mod.open --name <mod>`, whose `init` reads a JSON file and calls `openOverlay(...)` or `setShared("files-actions.request", ...)`, then closes itself. A request carries its own `root`, so the live panel runs it against a scratch folder. A mod can only import from its own folder: copy the modules it needs into it. Every overlay takes the keyboard from the owner while it is open, so keep these runs few and short, and delete the mod afterwards (`.gitignore` never tracks it).
- `cx.spawn(body)` runs `body` up to its first `await` at once. Called from `render()`, that first step is inside the draw: `cx.notify()` there is refused and ends the task without a word. A task begun in `render()` that does more than read should `await` first.
- `herdr-app shot` shows no focus ring and no selection in the editor while Herdr is not the active app.
- Write a new mod's `mod.json` before anything else in its folder. A folder Herdr first sees without one is docked into the shown layout by itself, as a new block at the end of `layouts/main-folders.json`: take that block out again.
- Saving a file under `mods/` reloads mods and cuts off their running tasks, also those of a mod that was not saved. Wait a few seconds after a save before sending a request, or it is taken and never answered.
- After an `await`, `props()` may answer for another copy (the one that drew last). Read it in `init` or `render` and keep what it said.
- `herdr-app check` shows nothing a mod logs. To time code in Herdr's own engine, make a throwaway mod whose `init` does the work and throws an `Error` with the timings as its message: the check prints it. `init` is stopped at 500 ms like an event handler, so time a few things a run. `node` is many times faster and says nothing about it.
- An overlay opened for a test is closed with `herdr-app do overlay.close` (the top dialog or popup), or `--id o<n>` for a window: the ids count up from `o1`. A window is closed by opening another under its `key` and closing the id that returns: `overlay.close --id` with a guessed id answers `ok` whether or not it closed anything.
- Keys in a mod's text fields. A field (and the editor's text) binds Up, Down, Tab, Cmd+F and more, and passes nothing on, so a binding has to sit as deep as the field to win. Up to Herdr 0.1.16 a `keys.json` section called `mod:<x> > Input` did that, because Herdr pasted the name into a key-context expression. Since 0.1.17 (`src/keys.rs`, `tab()`) a section's name is one literal mod name: such a section is still valid and listed by `keys()`, binds nothing, and writes no `keys.error`. So `go-to-file`, `project-search` and `file-editor` install that section's keys themselves with `cx.bind_keys`, under the context `mod == <x> > Input` and with the same actions (`fieldkeys.js`). Herdr runs every script action at the window root (`run_action`), as it runs one from `keys.json`, so the command reaches `nextCommand()` unchanged. Herdr drops all bindings whenever `keys.json` changes and puts back only its own: the mods bind again when `keys()` changes, from `render()` through a task (binding is refused in `render()`).
- What people read: `README.md` is the tour (a picture and a few lines for each feature, the keys to copy, Install), and `docs/<feature>.md` is each feature's whole reference. A change to what a feature does goes into its page, and into the README only when the tour's few lines are no longer true. Say a thing once: what holds for every feature is in the README's "The same everywhere".
- The pictures in `docs/images/` are the real app, shot with `herdr-app shot` in a sandbox, never the owner's window: a second Herdr with its own core and home (`HC_SESSION`, `HERDR_APP_HOME`, `XDG_STATE_HOME`, as Herdr's own `scripts/sandbox` does, plus a fake `HOME` on a short path, since a socket's path holds about 100 characters), fake projects, stand-in agents that print a screen and report `\033]7501;state=working:app=claude-code\033\\`, and stubs first on its `PATH` for `docker`, `ddev` and `gh`, which would otherwise answer with real projects. No real project, session or machine name may show: `herdr-app` is the one real name allowed. With the screen locked no window is the active app, and the mods read nothing: retake pictures with the owner at the screen, or with the sandbox's copies told the window is active. Don't put the fake home under `/private/var`, `/private/tmp` or `/tmp` when the Usage dialog is in the picture: it files those under "Other folders". Every picture is one canvas of 1680×1050 (the README's column at 2x; the overview is 2520×1575, the same shape) with one backdrop (a gradient from `#b7c3d3` down to `#8d9bb0`, corners of 24) and parts of a shot on it as cards: at the app's own pixels, never scaled, each with rounded corners, a hairline and a shadow, and cut by the canvas's edge when larger than it. A small feature is shot at a higher zoom, not enlarged. They are saved as lossless WebP. A shot leaves out the window's three buttons, which the system draws: where a picture shows the window's top left corner they are drawn back in. While the sandbox is in the background a mod takes a request left in shared state only when it draws, and nothing makes it draw: follow a request with `herdr-app shot`, which does, or the request goes stale.
- When a question is about how Herdr delivers an event or a key, read its source at the installed version's tag instead of guessing: the GPUI fork is under `vendor/gpui-pre`, the script bridge under `vendor/gpui-kit/crates/shell`.
- After Herdr updates (`herdr-app --version` newer than the version named under "What is custom"), follow `.claude/skills/herdr-update/SKILL.md`. It holds the whole check: the clones against their originals, the changelog and the source, sorted against this setup, with a report for the owner. What each check found, and what is still open, is logged in `checks.md` beside it. The clones get no update from Herdr, so this is how they keep up.

## Git

- `.gitignore` is an allowlist: everything is ignored unless listed. A new mod, layout, theme or root file needs a line there.
- **This repository is public. Before every commit, read the staged diff (`git diff --cached`) and make sure it holds nothing that should not be public:** no secrets, tokens, passwords, API or SSH keys; no personal information (names, email addresses, phone numbers, addresses); no home or project paths (`/Users/...`, `/Volumes/...`), machine or host names, client or project names; nothing else private or security-sensitive. This applies to every committed file, including settings, key bindings, notes, screenshots and commit messages. If something like that is needed locally, keep it in an ignored file. The deliberate exceptions: the owner's name in the `NOTICE` copyright line, and the author name and email that git takes from its own config for a commit. The owner's email address must never appear in any file. If you are unsure whether something is safe to publish, stop and ask before committing.
- Never track state: `shared.json`, `view.json`, `data/`, `layouts/.state/`, or anything Herdr ships. State holds space names, folder paths and project names.
- Commit messages follow Conventional Commits: `<type>(<scope>): <description>`, then an optional body and footers.
