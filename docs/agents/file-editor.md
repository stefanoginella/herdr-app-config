# `file-editor`

Notes for agents on the mod in `packages/file-editor/mods/file-editor/`. The index and what holds for every mod are in `AGENTS.override.md`.

A text editor that opens as a pane beside the terminals. It is not a clone: Herdr ships nothing like it. One editor a tab, its open files as a strip of tabs; long lines wrapped or not (a file at a time), save, find and replace, Markdown shortcuts and a rendered preview where the find bar's matches are lit, previews of images, PDFs, CSV, SVG and HTML, a file status bar, comment and line commands, and marks where a file differs from the last commit.

## What is where

- `main.js`: the pane. `load()` opens a file; `changed()` and `entered()` follow the typing; `look()` reads the file again and `take()` shows what it found; `save()`; `tabAction()` pins or closes tabs; `search()`, `step()`, `replaceOne()`, `replaceAll()` are the find bar; `cursor()` and `at()` are where finding goes on from and lands, in the text or the preview; `page()` draws the preview; `unpreview()` and `bring()` go back from it to the text; `show()` and `cycle()` change the tab shown (a mouse's back and forward buttons too); `command()` runs a key command or a button; `requests()` takes requests from the Files panel and tab menu.
- `preview.js` classifies files, reads disk size and identity, stages binary assets under ignored `data/file-editor-preview/`, renders single PDF pages with Poppler, and normalizes the first frame of a raster image to a bounded PNG before showing it. It also measures SVGs and builds bounded CSV table pages with source spans. Remote copies stream through `hc exec` in 4 MiB blocks because the core caps stdout at 8 MiB. SVG and HTML snapshots use the current text including drafts. Paths are arguments, and temporary assets get new paths on every revision so GPUI reloads the image.
- `html-preview.py` serves a file and its Git tree (or its containing directory) through a token-protected loopback HTTP server. The snapshot serves the draft with a script-free Content Security Policy and uses local headless Chrome or Chromium. Open in Browser serves saved content, supports relative project assets and expires after 15 minutes idle. Remote paths stay on the core and are read through `hc exec`. Requested assets must resolve inside the served root.
- The footer uses disk metadata from `measure()` or `refreshPreview()`, text counts from `textStats()`, and dimensions or counts from the media and CSV readers. It distinguishes the on-disk size from the counts of the current text. Character counts are Unicode code points, and a trailing line break leaves a final blank line.
- `remote.js`: saving a file on another machine. Its header says how. The script in it runs under any `sh`, so it is tested with a local one, and against a real machine through `hc exec --on`.
- `diff.js`: which lines of a text differ from an earlier one (`compare()`), and where a mark's lines are (`range()`). Like `edit.js` it touches nothing of the app and runs under `node`. In `main.js`, `head()` reads the file as the last commit has it, `mark()` and `remark()` work the marks out, `ruler()` draws them and `change()` goes to one.
- `edit.js`: what each text command does to a selection, and how to detect web URLs and map selections between Markdown source and preview. `indent()` says how a file is indented (`tab_size`, `hard_tabs`), from its name and its lines. Nothing in it touches the app, so test changes to it under `node`.
- State: the open files in strip order, whether each wraps or is pinned, CSV column widths and unsaved text, in the copy's `localStorage` (one store for each tab, since the props are `{ tab }`). Shared `file-editor.open` (`{ tab, path, on, at }`) holds a request only until the tab's editor takes it; shared `file-editor.moved` (`{ from, to, on, at }`) is the last rename or move the Files panel made. Shared `file-editor.shown` (`{ tab: { path, on } }`) is the file each tab's editor shows, written by the editor (`tell()`, `say()`) and read by the Files panel; a tab whose editor shows no file has no entry. The tab menu is a popup copy of the same mod. It sends `file-editor.tab-action` (`{ editor, tab, name }`) with the pane instance token and file tab's serial so only the issuing pane can handle it, even if the file moved while the menu was open.
- The text is the terminals' size (`textSize()`: `settings().font_size`, as Herdr's own Files preview has it since 0.1.17), set on the `Editor` element so a change applies at once; `rowHeight()` takes that size. `name()` names the pane after the file shown, and `TITLE` ("File Editor") with none (`pane.rename`: a mod pane's own title is its folder's name, and Herdr has no other way to set it), only when its name is empty, `TITLE`, the last one this copy gave, or an open file's (a name kept across a restart): a name someone gave the pane stays.
- `reveal()` shows what the Search panel found: a request in `file-editor.open` may carry `select` (`{ line, start, end }`). `travel()` is the three moves of the cursor it shares with `change()`. The command `search-project` toggles the Search panel, offering it the selection only when showing it.
- `fieldkeys.js`: installs the keys of the section `mod:file-editor > Input` (see "Keys in a mod's text fields" under Working here in `AGENTS.override.md`). The same file is in `go-to-file` and `project-search`: keep the three the same.
- Key commands in `mod:file-editor` in `keys.json`: `save`, `find`, `replace`, `find-next`, `find-prev`, `escape`, `preview` (Cmd+Shift+V and Ctrl+Shift+V), `close` (Ctrl+W), `bold`, `italic`, `code`, `strike`, `link`, `bullets`, `numbers`, `tasks`, `comment`, `line-up`, `line-down`, `duplicate`, `next-same`, `next-change`, `prev-change`, `search-project`. The native text-field section repeats the close, preview, find and project search bindings. `wrap`, `preview` and `open-link` are in the palette.

## Behavior to preserve

- The timed look at the file shown (`poll()`, every `LOOK_TICK`, a look at most every `LOOK_EVERY`) is skipped while Herdr is not the active app; the first tick with Herdr active again looks at once (`away`), since the file may have been changed in another app. Saving, a request in `file-editor.open`, `requests()`, a tab shown or clicked and the editor taking the keyboard call `look()` and `head()` themselves and don't wait for it.
- The editor writes `file-editor.shown` only when the file it shows is another one than the last it told (`tell()`), and takes its entry out when the pane closes. Setting shared state draws every mod again, the editor too: a write on every render, or one that depends on what another copy wrote, would never end.
- Nothing is saved until asked. A save passes the text last read from the file (`base`) to `writeTextFile`, which refuses when the file is no longer that: the editor then asks, and never writes over a change it has not shown. `base` is `null` only when there is no file, and a save then creates it.
- A change on disk replaces the text only when nothing is unsaved (`take()`). With unsaved text it becomes a question (`notice: "changed"`), and "Keep my text" only moves `base` to what is on disk: the text stays unsaved.
- Unsaved text is put in `localStorage` as it is typed (`stash()`) and when the pane closes (`close()`), with the `base` it began from. `close()` can't ask anything, so this is what keeps a closed pane from losing text. A restored draft whose file changed meanwhile becomes the same question.
- Tab labels are cached per set of open paths, invalidated on open, close and move. `edit.tabLabels()` adds parents only for colliding names and includes the machine for identical paths. The editor palette action `file-editor.reveal` shows the File Explorer block and passes its active tab, file and machine to that panel.
- Pinned tabs stay to the left in the strip. All bulk close actions skip them. An explicit close still works on a pinned tab. Close Others and Close to the Right use the right-clicked tab, including when a different file is showing.
- `closeFiles()` and `advanceClose()` close clean targets together, then ask about the remaining targets in strip order. Cancel leaves all remaining targets open. A save in flight keeps its editor state until it finishes. A failed or stale save leaves the draft open, and the disk notice remains available during the close. A restored draft counts as unsaved even while its file is loading.
- Only whole files are edited: one cut short at `MOST` characters is read-only.
- A file on another machine is saved by `remote.js`, since `writeTextFile` is local: a shell script run there with `sh` through `exec`, the text as its arguments, in pieces of `PIECE` characters (one argument holds about 128 KB on Linux). Nothing is installed there. It keeps the same promise as a local save: it reads the file's checksum (`cksum`) and text in one call, refuses when the text is not `base`, and with the last piece refuses when the checksum is no longer that (`Stale`). The check and the write are not one step: a change landing in between is lost.
- The remote script writes into the file (`cat > file`), never moves a new file over it: a script stays executable, a symlink stays a link. Don't change that to `mv` for atomicity.
- The script's values are its arguments (`$1`…`$6`), never part of its text: a path or a file's content must not be put into the script string.
- A save that is cut off (the pane closes between two pieces) leaves a hidden `.<name>.herdr-<random>` file next to the file on that machine. Nothing clears it.
- A file from another machine with a character that could not be decoded (`\ufffd`) is read-only: it is not UTF-8, and a save would write it back as something else.
- An edit is `set_selected_range`, then one `replace`: one undo step. `set_value` is only for text read from disk, since it drops the undo history.
- The editor's own keys win over the `mod:file-editor` section while the text has the keyboard: undo, redo, Enter, Tab, Cmd+Alt+Up/Down, Cmd+[ and Cmd+], and Cmd+F and Cmd+Shift+F, which Herdr's code editor takes for a search of its own that draws no bar (`searchable` in its source). Escape passes when there is one cursor.
- Keys that need to win inside a native text field are in `mod:file-editor > Input`, installed by `fieldkeys.js` under `mod == file-editor > Input` at the same depth as the native bindings. Keep them in `mod:file-editor` too, for the preview and other pane surfaces. Ctrl+W goes through the normal tab close flow and leaves the terminal binding alone.
- List continuation happens in `entered()`, on the editor's `submit` event, which comes after the line break is in: `edit.continued()` compares the text before and after. It must not run on `change` alone: an undo that brings a line break back looks the same.
- The editor paints a selection only while it has the keyboard, so a match is not highlighted while the find field has it. The find bar says its line instead, and that line is a button (`goTo()`, also Cmd+Enter in the field) that moves the keyboard to the text with the match selected. Don't do that on a plain Enter: the next key would type over the match. In the preview every match is lit (`page()`, `highlight_range`), the current one in the theme's yellow, at most `LIT_MOST`: each is a call in `render()`, and the matches are found by `search()`, never in `render()`.
- Herdr exposes one selection and no scroll position of the editor to a mod. So `next-same` moves the selection instead of adding a cursor, the text can't light every match (only the preview can), and nothing can stay pinned while the text scrolls.
- Herdr's editor has decorations and diagnostics of its own (`input/editor/decorations.rs`), but gives a mod none of them: nothing can be drawn beside a line. So the lines that differ from the last commit are marked on a strip that is a map of the whole file, right of the text, and shown by selecting them (`change()`). The strip is as tall as the file's lines would be without wrapping (`rowHeight()`: GPUI's line height, the font size times the golden ratio, rounded to a pixel of the zoomed window) and never taller than the pane. If marks in a short file stop being level with their lines after a Herdr update, that row height changed.
- The marks compare the editor's text, unsaved typing included, with the last commit (`HEAD`), not with the index: a staged change stays marked. A file git doesn't have, in a repository or outside one, has no marks, and neither has a read-only one. `head()` asks git for the file's object name (`rev-parse`) on every look, and reads the file itself (`cat-file`) only when that name changed.
- Herdr stops a script that runs too long: 50 ms in a render, 500 ms in an event handler or a task (`sandbox.rs`). It can't be caught. So `diff.compare()` never runs in `render()`, and it gives up on more than `MOST_EDITS` single-line edits, marking everything from the first difference to the last as one change: at 400 edits the search took 16 ms in Herdr, and its cost is the square of that. Time it in the app before raising it, with a throwaway mod: `node` is many times faster.
- Going to a change takes three moves of the cursor, a frame or two apart (`change()`): under the change, above it, then the change. The editor scrolls only as far as the start of a selection needs, which coming from above is the pane's last row, and of two moves made at once it follows the last only (`scroll_to_with_padding` in `input/base/state.rs`).
- The keys in `mod:file-editor` count only while the keyboard is inside the pane, and Herdr gives a mod pane no place for it. So the pane has its own (`this.handle`, on the root), and `focus()` puts the keyboard in the text or, when there is none to type in (the preview, no file), there. Whatever takes the text away must call `focus()`, or the keys stop until a click.
- A file asked for by the Files panel takes the keyboard twice: at once, and `REFOCUS` ms later, because Herdr focuses the pane after the click.
- What a search found is gone to (`reveal()`) `REFOCUS_SOON` ms after the file is asked for, never at once: the text may not be drawn yet, and Herdr focuses the pane after, which takes the keyboard from the text and with it the selection. If the file then turns out to have changed on disk, it is gone to again in the new text (`goal`). A file in preview goes back to its text (`unpreview()`): the page could light the result, but a TextView can't be scrolled to an offset, and the result may be anywhere in the file.
- In the preview, finding stays in the preview: `search()` and `step()` move the place (`d.place`), not the text's selection (`cursor()`, `at()`), and the page doesn't scroll to the match: the bar's "Go to line" (`goTo()`) goes to the text. What the reader selects in the page (`on_selection_change`, `s.range`) is the place too, and the `preview` command back to the text selects it there and brings it into sight (`unpreview()`, `bring()`), a moment later: the editor has to be drawn first. A cleared selection, a new preview and a text taken from disk forget it.
- `requests()` is called from `render()`: its task waits one step (`await null`) before anything else, or a request for a file already open runs in the draw, and the timer that goes to its line is refused.
- The pane also takes the keyboard when it becomes the focused pane (`arrived()`: its header was clicked, `pane.focus`), since Herdr hands a mod pane none. With the keyboard outside the pane, Cmd+F is the menu bar's Find, which fails on a pane without a terminal.
- The strip gives the keyboard to the text on the click, not on the press: the press gives it to the pane itself (`track_focus` on the root), after any handler of the press.
- A character typed over a selection wraps it (`typed()`, `edit.surround()`). It is caught in `on_key_down` on the element around the editor, which runs only for a key no binding took, before the character is typed, and stops it. It must stay there and not move to `change`: an undo can leave the same trace as typing a character over a selection. A character made by a dead key or an input method never comes this way, and is typed as usual.
- A new item in a numbered list counts the items under it on (`edit.continued()`), in the same edit. A list numbered `1.` all the way down stays so.
- A wrapped line starts under its line's own leading spaces: that is Herdr's editor, which offers a mod no other choice. The `wrap` command turns wrapping off for that file.
- Wrap is per open file (`d.wrap`, kept in localStorage, on by default), switched with `set_soft_wrap()` from a command. With wrap off the change-marks strip is exact; with it on, a mark below a wrapped line is lower than the strip shows, as before.
- The indent is worked out when a file is read and again when a read from disk replaces the text (`edit.indent()`: tabs for a Makefile or a mostly tab-indented file, else the most common step of 2, 4 or 8, from the first 2000 lines). Stock Herdr draws a tab character at a width of its own (about 2.4 columns at 0.1.18), so indent guides don't line up with tab indents. The optional [native patch](../native/README.md) positions guides from shaped glyphs and extends them through the carried indentation on wrapped rows. File Editor still passes the same tab settings to either executable.
- Images and PDF tabs have no EditorState. Save, text selections and text-only commands have no effect in those tabs. PDF changes render one page at a time. Cache files are removed when replaced or the tab closes, and old directories can be pruned on a later load.
- Binary preview jobs use the disk stamp to skip unchanged media. Text previews are keyed by source and path. Keep slow work outside the draw and ignore stale completions after a file moves, closes or changes. CSV parsing and counts run outside the draw, and the table renders only the visible rows of the active row and column pages.
- Image jobs have an overall deadline, 20 seconds locally and 45 over SSH, in addition to per-command timeouts. An unchanged failed image is not automatically decoded again on each look. Reload or Retry starts a fresh attempt and an obsolete job cannot replace its result. Decode and verify the generated PNG first because the native image element has no error callback. The footer uses original image dimensions.
- CSV edits replace only the source span of one field, including adding any trailing missing fields when editing a ragged row. A retained multiline field is drawn in the expanded active row, with one mouse handler above the virtual list. Its hit test uses the current widths and the list's logical scroll offset. A column grip tracks the window until release, using the zoom factor to convert window coordinates. Pending cell typing is included in stored drafts, applied as one text edit, or explicitly canceled. Do not refresh the CSV's source from disk underneath an open cell field. A save still uses the editor's expected-base check.
- The Markdown preview shows raw HTML as text (`raw_html(false)`). Plain web URLs in prose are passed to TextView as angle-bracket autolinks, with an offset map that keeps find highlights and selected source ranges in the original draft. In source, modifier-click reads the caret after the native mouse dispatch rather than measuring text. CSV URL cells use the grid hit test. Static HTML and SVG snapshots show links in a separate bar, not on the image.

## Trying it

- `file-editor`'s key commands run from a shell (`herdr-app do file-editor.save`), on the editor of the tab shown. Its selection and what is typed can't be set from there.
- `file-editor.toggle-pin`, `file-editor.close`, `file-editor.close-others`, `file-editor.close-right` and `file-editor.close-all` use the active file tab when invoked as commands. The menu can use any file tab.

- `file-editor.page-prev` and `file-editor.page-next` drive PDF pages and CSV row pages. `file-editor.refresh-preview` retries media or regenerates a static snapshot. `file-editor.open-browser` opens the saved HTML file with the system browser.
- Sandbox checks covered images, page navigation in PDF and CSV, SVG rendering, and HTML with linked CSS and an image. A paired loopback core exercised remote paths and a 12 MiB binary transfer. A headless browser exercised the interactive server and ran the saved page’s script. The app’s previews and status bars were checked with screenshots. Pointer interactions and typing were not exercised by hand.
- The inline CSV and image retry changes were checked in a separate 0.1.18 window. A scripted cell edit preserved the UTF-8 BOM, CRLF records and untouched multiline quoted field. A corrupt PNG showed Retry, and simulating a stalled preview produced a timeout and recovered on retry without accepting the delayed result. Pointer drags, link clicks and physical shortcuts were not exercised.

- The screenshot sandbox showed two same-named files with distinct parents and revealed the current file from a hidden right panel. The native screenshot shows three literal tabs and a wrapped line. The patch’s Rust tests cover measured tab positions, mixed leading spaces and tabs, and carried indentation.
