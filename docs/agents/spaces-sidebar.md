# `spaces-sidebar`

Notes for agents on the mod in `packages/spaces-sidebar/mods/spaces-sidebar/`. The index and what holds for every mod are in `AGENTS.override.md`.

A clone of Herdr’s `spaces` sidebar (from version 0.1.18) with folders, agent counts, container controls and local DDEV service links.

## What is where

- `main.js`: the sidebar. `arrange()` reconciles the model with the open spaces and syncs the real space order to it with `space.move`; `section()` draws; `row()`, `folderRow()`, `emptyRow()` and `tail()` carry the drag-and-drop handlers.
- `model.js`: the folder state and every change to it. Always `load()`, change the copy, `save()`.
- `menu.js`: the right-click menus (space, folder, root). `naming.js`: the new/rename dialog. The mod opens itself for both, with `props().menu` or `props().naming`.
- State lives in shared `space.folders`: `{ root: [spaceId | { id, name, folded, on, spaces }], projects: { projectKey: folderId } }`.
- Folded machine headers and reconnect bookkeeping use the mod’s localStorage in `data/spaces-sidebar/store.json`. The package rename keeps shared `space.folders` and `space.colors` as they were.
- Folders are per machine: `on` is the folder's machine (null for this computer), and it holds only that machine's spaces. `model.moveSpace()` and `admit()` refuse a folder of another machine, a drag only aims within one machine's part, and `section()` draws a machine's own folders under its header. New folders go on the shown space's machine, or the machine whose header was right-clicked. `load()` splits a folder holding several machines' spaces (and one from before `on`) into one per machine (`<id>~<machine>`), and `save()` writes that once.
- `open.js` handles requests for opening a space's local project in an external app. The menu leaves the request in shared `spaces-sidebar.open`. The sidebar takes it and runs it through `external-apps.js`, which reads the [shared preferences](../external-apps.md). Keep its copies in `file-explorer` and `project-search` identical.
- Key commands: `spaces-sidebar.new-folder`, `spaces-sidebar.fold-all`, `spaces-sidebar.unfold-all`. None is bound; all three are in the command palette (`palette` in `mod.json`).
- A folder's header shows a + while the pointer is on it (`hotFolder`; not in the rail, not during a drag): `newSpaceIn()` unfolds the folder and makes a space in the home folder of the folder's machine (`$HOME` read there with `sh`), through `exec("herdr-app", ["do", "space.new", …])`, which prints the new space's id (`run()` returns null), and files that id into the folder with `model.moveSpace()`. The menu leaves its folder ID and timestamp in shared `spaces-sidebar.create`. The sidebar consumes it once and calls the same `newSpaceIn()`. Old `next` records are ignored.
- `names.js`: what is drawn while names are hidden (see `hide-names.md`): `folderNames()` gives every folder a made-up name none other has, by id; `space()`, `machine()`, `repo()`, `branch()` and `stack()` are the real name while names are shown. The menus use the same.
- `stacks.js`: a space's containers, the DDEV projects and Docker Compose stacks of its project folder (its repo's top, else where it is). `stackButton()` in `main.js` shows them at the row's end: the glyph says what they are (`site.svg` for DDEV, Herdr's `icons/docker.svg` for Docker), a dot how they are (green running, amber in part, none stopped, as the machine header's dot means live), a spinner while one starts or stops and starts or stops them on a click; the space menu does it one stack at a time and opens a running DDEV site. A dev container's stacks (`dev`) have a second button of their own after it, with `devcontainer.svg`, so a click on the project's button never starts or stops them; `stacks.title()` names a stack wherever it is shown ("Dev container <project folder>", not the compose name VS Code made up). `sessionBadge()` puts the number of the space's agents (`agents()`) on its avatar's top-right corner, clear of its letter, filled with the most urgent one's color (idle: a ring); `cutout()` rings a mark in the row's color, the sidebar's under the translucent selected one; an idle agent marked unread in `mark-agents-unread` counts as done.

## Behavior to preserve

- The sidebar's order is the truth: the real space order follows it, so `space.next` and `space.select:N` match what is drawn.
- Placement is by space id. `projects` remembers which folder a project (its repo, else its folder; never the home folder) was filed in, so a new space on that project lands there. A loose space that `cd`s into a filed project joins its folder; a filed space never moves by itself.
- A closed space is pruned only after its machine's layout has been readable for 5 seconds and still lists at least one space. Before that, a missing space may only be unlisted while a layout loads, and pruning would lose placement.
- A popup is as tall as its content, so the menu's root must not scroll (it collapses to nothing). A long folder list scrolls inside a fixed height. If the stack and service actions also overflow, all rows scroll together in one fixed-height child. Track keyboard selection by row identity as late app and service choices arrive.
- A worktree space is drawn under its repo's space and follows it: it is clicked, never dragged.
- What runs comes from one `ddev list --json-output` and one `docker compose ls --all` per machine (`stacks.lists()`), every `STACK_POLL` and only while Herdr is the active app; stacks never brought up come from one `find` per project folder (`stacks.FIND`, every `STACK_FIND`), at most `DEPTH` folders down and never into `SKIP`. Never one call per project per tick. Time a change to `FIND` on the biggest project. The pure parts of `stacks.js` run under `node` with a stub of `herdr`.
- A folder too wide (`tooWide()`: a home folder or one holding it, or one just under the root) is not looked in, and a folder with more than `MANY` stacks shows none: it holds projects, it isn't one.
- A compose stack whose containers exist is started with `compose -p <name> start`, never `up`: a dev container's stack is made from files that may be gone. Only a stack never brought up is made with `up -d` in its folder. Stop is `stop`, never `down`. DDEV's own compose stacks (`ddev-*`, files under `.ddev/`) are its projects, not stacks of their own.
- The menu never runs `ddev` or `docker` itself: it leaves a request in shared `spaces-sidebar.stack` (`stacks.request()`), and the sidebar takes it (`stacks.take()`, in a task that waits one step) and runs it.
- **Open site**, **Open Mailpit** and **Open Adminer** pass the selected local HTTP(S) URL to `cx.open_url()`. Mailpit comes from the machine list when the router is enabled. On a right-click, the sidebar starts one `ddev describe --json-output --skip-hooks` per running local DDEV project in that menu. The popup takes the matching promise in `init` and offers Adminer only for a running service with a URL. Prefer the scheme of the project’s primary URL. The only URL hint is the site’s, suppressed while names are hidden. The stack scan uses `sh`, `find` and Unix-style paths. Native Windows stack discovery and path matching need separate support.
- A dev container's stack is a compose stack with a file in a `.devcontainer/` folder (`readCompose()`, `dev`: the folder that holds it, which is its `dir`). It is known only once VS Code or the devcontainer CLI has made it (`FIND` never enters `.devcontainer`); one built from an image or a Dockerfile alone is no compose stack and never shows. It never stands for a compose file found on disk: its first file may be the project's own `../docker-compose.yml`, and the project's stack, never brought up, would be hidden behind it.
- The stack button stops its press (`on_mouse_down`) so the row begins no drag; it does not stop the release, which `on_click` needs.

The screenshot sandbox consumed a folder-menu creation request, unfolded the named folder and filed the returned space ID there. `creation.test.mjs` covers an unrelated space appearing first on the same remote machine.

The screenshot sandbox showed all three DDEV links. Calling the Mailpit and Adminer menu actions delivered the expected project URLs to the sidebar’s browser handler. Removing Adminer from the project description removed its action on the next open. `services.test.mjs` covers custom ports, scheme selection, and missing or stopped services. The browser targets were checked programmatically. Physical clicks were not exercised.
