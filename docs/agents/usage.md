# `agent-usage`

Notes for agents on the mod in `packages/agent-usage/mods/agent-usage/`. The index and what holds for every mod are in `AGENTS.override.md`.

How much of the AI agents' limits is used, whether each will last the week, and where the usage went. It is not a clone. A dialog (`mod.open:agent-usage`, the palette's "Usage", `cmd-shift-u` in `global`), and a glance of the same readings: a widget above Spaces. Tokens are the unit everywhere (input, output, cache write and cache read together); dollars are a side figure: Claude Code's own cost for Claude, an estimate from OpenAI's API prices for Codex, shown with "≈".

## What is where

- `collect.mjs`: the collector, one Node file without dependencies, run with `node` here and, as `node --input-type=module -e <its text>`, on every connected machine. Its header lists the flags and the document it prints (v3). It reads Claude Code's transcripts (`~/.claude/projects`) and cost records, Codex's sessions (`~/.codex/sessions`), the limits file the owner's statusline writes (`~/.claude/statusline/.usage-cache.json`), Claude Code's own older counts (`~/.claude/stats-cache.json`), and dev containers through `docker`. It uses `rg` when there is one. `collect.test.mjs` tests it under `node --test`, with a fake `docker`.
- `CODEX_PRICES` in `collect.mjs`: USD per million tokens `[input, cached input, output, cache write or null]`, from OpenAI's pricing page, standard tier, prompts under 272K tokens (the long-context surcharge is ignored), the cache write at the 30-minute price (the page also lists a 12-hour one); the comment says when it was fetched, and which price is promotional. `codex-auto-review` has no public price: it is priced as `gpt-5.6-luna`, an assumption the owner chose. A cache write without its own price is priced as input; reasoning tokens are in Codex's output already. A model not in the table has no price (cost null, "no price" in Models). To update: edit the table and its date, then run the tests.
- Codex's weekly limit: every `token_count` event's `rate_limits` with a 10080-minute window, grouped by its reset (`CODEX_JITTER_MS`), is that window's trail (`limits.codex.week`); the earlier windows' trails are kept in `limits.json` (`codexWeeks`) and printed as `limits.codex.weeks`.
- `main.js`: the dialog, in three zones. Will it last: the headline (`headline()`), one budget ruler per limit (`rulers()`, `ruler()`, `ticks()`), then `charts()`: one `column()` per weekly limit with a reading (Claude, then Codex), side by side at equal widths, each its title, its time chart (`week()`, `chartShapes()`) and its own Burning now (`side()`, `burning()`: that agent's projects of the last hour, and what 1% of its week costs); narrow, one column with the switch (`switcher()`). Where it went: `toolbar()` (the range tabs, the filter, the range's tokens, their split, the dollars), `projects()`, `middle()` (`bars()` and Biggest sessions), `models()` and `machines()`, whose model groups and machines with containers fold (`groupHead()`, `fold()`). The year: `year()` (the calendar, its records, `earlierWeeks()` per agent, across the whole width). `fit()` lays it all out for the dialog's size (see "Behavior to preserve" below). `collect()` runs the collectors and reduces what they said; `reading()` works out the verdict, the rulers and the limit most in danger; `palette()` gives each project its color; `name()` and `machineName()` give every name drawn, made up by `alias.js` while names are hidden.
- `reduce.js`: everything shown, worked out from the collectors' documents (`prepare()`, `weekView(data, now, agent)` for each agent with a weekly reading, `rangeView()`, `yearView()`, `burning()` for each agent's Burning now). `pace.js`: the statusline's pace, ported. `limits.js`: a reading as words and as a block (`fromCache()`, `limitBlock()`, `danger()`, `byDanger()`, `judge()` for the verdict of several limits, `verdict()` for one, `short()`). None of the three touches the app: they run under `node`, each with its `*.test.mjs`.
- `glance.js`: the sidebar widget (`side()`, and `rail()` when the sidebar is narrow); `readCodex()` and `codexLine()` read Codex's latest reading. `agentIcon()` draws an agent's icon (Herdr's `icons/claude.svg`, `icons/codex.svg`, in full color) wherever an agent is named, in the glances and the dialog: the rulers, the charts' titles and switch, Burning now's columns, the Models groups, Biggest sessions' second lines, Earlier weeks.
- Props: none for the dialog; `{ role: "side" }` in the layout.
- State in `~/.local/state/herdr-usage/` on each machine: `history.json` (the day rows, kept past the 30 days Claude Code keeps its transcripts; never an estimate), `limits.json` (each weekly window's readings as they rose, by its reset: `claudeWeeks`, `codexWeeks`), `containers/` (what was read from each dev container) and, here only, `view.json` (what the dialog showed last, shown at once at the next open; `SNAPSHOT_V` 6; and `folds`, the folded model groups and machines by id: `claude`, `codex`, `machine:<name>` with `here` for this Mac). Shared state holds `names.hidden` and `agent-usage.limits`, the last collection's limit readings and its timestamp. The limit in focus is in the dialog's memory only.
- Key commands: `agent-usage.refresh`; `agent-usage.day`, `agent-usage.week`, `agent-usage.month`, `agent-usage.all` for the range; `agent-usage.names` to hide or show names (the window's `names.hidden`, as `hide-names.toggle`); `agent-usage.claude`, `agent-usage.codex` to put that weekly limit in focus (it shows only when the charts take turns; side by side, the command, like a click on a ruler, changes nothing on screen). None is bound: the dialog takes `1` to `4`, `r`, `h` and Escape itself while it has the keyboard, and the others are for a look from a shell. Escape clears the project filter first, then closes (`closeOverlay` with the id read in `init`): Herdr's own Escape doesn't reach a dialog that holds the keyboard. The header's × (Herdr's `mods/pane/close.svg`, after refresh) closes it the same way, at once.

## Behavior to preserve

- It only reads, and it asks the network nothing. The limits come from the file the statusline writes and from Codex's own session files, never from Anthropic's undocumented usage endpoint or the Keychain: other mods that use it report it refusing for hours.
- Tokens are the unit: bars, sparklines, the order of projects and their shares, machines, models, sessions, the calendar and the change against the period before. A token is a token whatever kind it is (input, output, cache write, cache read).
- Every Claude Code session's statusline writes the limits file with the reading of its own last reply, so an idle session puts an older, lower one back (57% after 59% was seen). Inside one window the reading only rises: the collector (`claudeLimits()`) and the glances (`limits.fromCache()`) take the highest of `sevenDay`, `week.peak` and the samples of the same window, and the trail in `limits.json` only takes a rise. Keep the two the same.
- Codex's weekly trail only rises too, at most one point an hour (`risesHourly()`). Readings belong to one window when their resets are within `CODEX_JITTER_MS` (3 hours): `resets_at` jitters by a few seconds between readings and was once seen 90 minutes off. OpenAI has also moved a window by about 13 hours and ended one early; those stay windows of their own. The weekly window may be `primary` or `secondary`.
- `pace.js` must give what the statusline gives: `pace.test.mjs` runs both on the same readings. Time is usable hours, 08:00 to midnight; the statusline's `CLAUDE_DAY_START_HOUR` can't be seen from here. Codex's week is measured the same way.
- Claude's cost is Claude Code's own (`cost-state` lines), never a price table: a session's cost is spread over its replies by weight, and a reply of a session without one gets its model's average. A resumed session's cost-state goes on counting from its parent's: each session gets only what it added.
- Codex's cost is an estimate from `CODEX_PRICES`, worked out when the document is printed (rows, `recent`, `top`), from history's rows too, and never written to `history.json`: a new table re-prices the past. Every amount carries its estimated part in dollars (`est`), and says "≈" only when that part is 5% of it or more, so a Codex-only figure always does and a Claude figure with a few Codex dollars doesn't. Under a dollar it says "<$1".
- A reply is counted once, by its message id, across every file. A Codex session is its thread and the sub-agent threads forked from it (one `session_id`).
- Dev containers are read through `docker` (`docker ps -a` by the label `devcontainer.local_folder`, `docker cp`, `docker exec`), never through `~/OrbStack/docker/volumes`: a program Herdr starts hangs for ever reading that folder, and on Linux the volumes are root's. Every `docker` child has a timeout and is killed at it; no docker, or one that doesn't answer, leaves that part out (`took.docker`). An exited container is read once (`FinishedAt`), a running one only where its files changed. A volume whose container was removed is no longer read: what was collected stays in `history.json`.
- A container's rows have its project's real folder (the label), so its usage is its project's.
- Nothing is added up while drawing. `collect()` reduces in a task, in steps; `render()` reads. Every shape (the charts, the rulers' hatches, the sparklines, the calendar's cells) is made once per data version and size, in a task (`shape()`, `build()`); a chart's key has its agent and its size, so two charts make two sets. A draw took 6 ms in the app with both charts.
- The snapshot kept for the next open is the reduced figures (about 90 KB), never a collector's document.
- The dialog collects every 5 minutes while it is open and Herdr is the active app, every 2 while an agent is working. The glances never run the collector.
- The rulers come first, all alike: weekly limits (Claude, then Codex), then shorter windows when there is a reading of one. A ruler is never dimmed for not being in the chart. Its x axis is percent of the limit: what each colored project ate (in the order of its points, scaled so the segments add up to the reading), "other", the hatch of what this pace will burn (to the end when it runs dry first, in the level's color, muted when on pace), the even pace's line, and under it a tick at the even pace of each local midnight. A window under a day has hour ticks and one plain fill. The hatch is a `Background.pattern_slash` painted on a rectangle path: `.bg()` takes plain colors only.
- The lists that scroll inside the body (Projects, and Models with three columns) are each wrapped by `contain()`, whose `on_scroll_wheel` stops the event while the list has more than it shows (its `ScrollHandle`'s content taller than its viewport): a scroll area doesn't stop the event, and the body scrolled with the list. A list that fits lets the wheel through to the body. The handler is on a wrapper, not the list, so it runs after the list has scrolled. Not tried by hand when this was written.
- The rulers are spaced with margins: a `gap` on their columns was seen to space nothing.
- The verdict speaks for the weekly limit most in danger (`danger()`: dry, then runs dry before its reset, then tight, then the higher projection) and names its agent; with two weekly limits both on pace its first line names both. There is one run-out time a limit, rounded to the half hour: the headline, the ruler, the chart's marker and the sidebar say the same. A burst (Claude only: the statusline's samples) is the verdict's second line and a second dashed line, never another run-out time.
- Both weekly charts show side by side, one column per agent with a reading, of equal widths; with one reading, that one takes the whole width. Below `WIDE_CHARTS` (900 px) they take turns: one column, the limit in focus, with the switch (icons and names) in its title; the focus is the limit most in danger until a ruler or the switch is clicked. Side by side, a ruler's click and `agent-usage.claude` / `agent-usage.codex` set the focus silently: it matters only when the window narrows.
- The dialog's size: `mod.json` asks 1280 px wide and 0.93 of the window's height (Herdr reads a size up to 1 as a share of the window). Herdr 0.1.18 centers a dialog in a flex box: a width wider than the window shrinks to the window's (edge to edge, no margin), a height taller is cut off at the top and the bottom, so the height must be the share. A dialog without a height is as tall as its content, which collapses a root that scrolls. Nothing lets a mod size its own overlay.
- `fit()` lays the dialog out from the root's `on_size_change` (window px divided by the zoom): charts side by side from 900 px, the lower zone in three columns from `THREE_COLUMNS` (1000 px) and else two (Projects; bars and Biggest sessions) with Models and Machines in a row under them, the year in one row from `YEAR_ONE_ROW` (1000 px) and else the calendar over the records and Earlier weeks, the tokens' split in the toolbar from `TOOLBAR_SPLIT` (1060 px), the headline at 28 px from 1000 px and 22 under. Heights: when everything fits, the lower columns get `LOWER_MIN` (290) and the charts what is left, from `CHART_MIN` (120) to `CHART_MAX` (180), then the lower columns grow to `LOWER_MAX`; when it doesn't, the charts fill the first screen with the rest of "will it last" (to 160) and the rest scrolls. The fixed heights it adds up are constants (`HEADLINE_H`, `RULER_H`, `CHART_FIXED`, `TOOLBAR_H`, the year's): change them together with what they measure. Tried in screenshots at the default size (the whole dialog without scrolling, the owner's window 1148 px tall), at 1100 × 680 (charts side by side, "will it last" whole on the first screen) and at 880 px (the switch, two columns, the year in two rows).
- The used line passes through the readings on record (Claude's trail and samples, Codex's trail), with weight only shaping it between them: without a reading it is the weight scaled to end at today's. A limit's points are put on projects by cost (Codex's estimate); an agent with no cost at all in the window, by tokens.
- The change against the period before compares full days, today left out (24 hours: full hours), and is given only when Claude's rows cover that whole period: without that, 30 days said "822% more".
- The calendar ranks days with rows by tokens, both agents together, and days known only from Claude Code's own message counts within their own kind: the units can't be compared, their ranks can. Its records count a day as active when it has either.
- A project is tied to an open space only by the live folders of that space's panes, never by `space.folder`, which is where the space was made: most spaces here were made in another project's folder, and colors and the click on a name went to the wrong space.
- A project has one color on the whole page (`palette()`, six colors). The colors are claimed by the weekly limit most in danger first (its top four that ate a point or more), then by the other limits' (the same), then by the shown range's own biggest. Without the point a limit at 1% took colors from the range's biggest project. An open space's avatar color wins unless it is the green, which is the "spare" level's, or already taken.
- The weekly reading is the account's, so the project filter and a hovered project dim the other bands and segments, never take them out.
- The word that tells two same-named projects apart (`dim`) is shown only when both are rows of the Projects list being drawn.
- Hide names (`h`, the header's toggle, `agent-usage.names`) is the window's mode, shared `names.hidden` (see `hide-names.md`). Projects get `alias.project()` of their real name, so the same in every range and the same as their space in the sidebar; "Other folders" stays. Session titles get `alias.title()` (a session without one keeps "Untitled session" or "Codex session"); machines other than this one `alias.machine()`; containers `alias.project()` of their name, still marked "container". The word that tells two same-named projects apart is not shown while hidden. The snapshot no longer carries the letters (`alias`) the first build drew: an older `view.json` with them still reads, so `SNAPSHOT_V` stayed 6.
- Biggest sessions are those of the range (and filter) at or over the average of the range's, at least three when there are three, at most six, and only as many whole rows as the column holds under the bars (`room`, from `fit()`'s height, rows `SESSION_GAP` apart): three at the least height. Nothing is cut by the zone's edge. Each second line starts with the session's agent's icon.
- The range's bars are scaled to the range's own tallest, which reaches the top of the area (`BARS_H`, 100 px); the faint lines are at the largest round step that fits under it twice (`niceStep()`).
- In Models, each group's models under 1% of the range's tokens are one last dim line ("3 more, <1%") when there are two or more; a group's biggest model always has its row. With three columns the list still scrolls when the groups don't fit, and Machines stays pinned under it; with two, neither scrolls.
- "Machines" is a section title like "Models" (`title()`: the same size, weight, color, left edge and space under it), pinned under the scrolling model list behind a divider, with no total of its own. Its machines are drawn as Models draws its groups (a chevron's place, the name in semibold, their figures). A model row starts at one indent (`CHILD`), where a machine's name starts too, having no icon; a container starts one indent further, so it reads as the machine's.
- The model groups' headers, Claude and Codex, fold and unfold on a click, with Herdr's chevron (`mods/workspace-chrome/chevron-*.svg`, tinted dim), and so does a machine row with dev containers listed under it (its containers fold; it says how many when folded). The "Machines" title never folds. A machine without containers has no chevron and no click. A folded group keeps its header line and its totals. All are open by default. The folds (`claude`, `codex`, `machine:<name>`) are written to `view.json` with the snapshot (`fold()` saves at once), never to `localStorage` or shared state; a `machines` key left there by the first build is dropped when read (`cleanFolds()`).
- The year fills the width without growing taller: the calendar's pitch comes from the width left after the records and Earlier weeks' least width (`PITCH_MIN` 11 to `PITCH_MAX` 13 px, the shapes made once per data version and pitch), the records follow it, and Earlier weeks take the rest up to the right edge. Without earlier weeks the records take the rest.
- Earlier weeks: one row per agent, its label column (`EARLIER_LABEL`) and percentage column (`EARLIER_PCT`, the newest week's) the same for both rows. The bars spread over the room between them, at one pitch for both rows (from the room and the longer row), so the rows' weeks line up from the newest; a bar is 0.7 of its pitch and at most `EARLIER_BAR_MAX` (14 px) wide, and when capped the bars stand right-aligned against the percentage. As many weeks as fit at `EARLIER_PITCH_MIN` (the newest). Each week is a bar on a faint track of the full height, colored by where it ended (green, amber from 85, red at 100); a week that ran dry also has a 2 px cap in the foreground color on top, so dry and tight don't differ by color alone. One agent's bars are twice `EARLIER_H` (28 px) tall, so the block is as tall with one agent as with two. The pointer on a bar names the week at the title's right ("Claude, 9–15 Nov: 84%", "ran dry" for 100%; `weekSpan()`, `hoverWeek`), a line that is always there, so nothing moves.
- Burning now's rate has one decimal under 10 ("2.0%/h", "0.5%/h"), and is "<0.1%/h" under 0.05.
- A chart draws no dot per working agent: who works where is Burning now's (its pulsing dot and "N agents"). The chart keeps the now hairline and the dot on the line at the reading, a plain element over the shapes that pulses while a Herdr agent of that chart's kind works: it follows `agents()`, which must not make the chart's shapes again. A Codex agent (its program's key, or its reported app) counts on Codex's chart only.
- Each weekly chart has its own "Burning now" under it, from the collector's `recent` (the last 60 minutes), one entry a project and agent (`prepare()`, `burning()`), so sessions outside Herdr count too; Herdr's working agents of that agent only add their number, after a small pulsing dot in the working color, and the click; the project's dot is always its full color. A row is drawn muted when the project's last reply is older than `QUIET_MS` (15 minutes). A row's percent an hour is of its own agent's limit, at the week's own cost per point; a row with tokens and no cost (a model `CODEX_PRICES` doesn't have) at the week's tokens per point instead. Its rate is blank only when neither can be worked out. At most `BURNING_MOST` (3) rows, then a dim "N more" line; nothing in the last hour is one dim line. Both columns reserve the same lines, as many as the fuller agent has and at least one (`burnLines()`, `burnH()`), so they line up; what is not reserved goes to the charts (`fit()`). The heading's right end says what 1% of that week costs ("1% ≈ $11.70"), from 5% of the limit up.
- The glances read Claude's limits file and its age every minute, and Codex's newest reading every 5 minutes, only while Herdr is the active app. One `sh` (`CODEX_READ`) finds the newest session file in the last two day folders of `~/.codex/sessions/<year>/<month>/<day>/` and prints the last `"rate_limits":{` line of its tail. The folder is the script's argument. Of two Codex readings of the same window the higher wins, using the published reading or the saved snapshot as a fallback.
- Every successful dialog collection publishes its limit readings to the widget before saving the snapshot. The widget uses those readings on its next draw and discards polls started before the update. The refresh icon, available in the expanded and narrow sidebar, forces a poll of both agents and spins while it runs. A click on the readings opens the dialog.
- Another machine runs the collector under `env TZ=<this Mac's zone>`: Herdr's script engine has no `Intl`, and the days and hours of every machine must be the same ones.
- A machine that fails, or has no `node`, is shown as unreachable; the rest is still shown.
- The widget says whose the words are: its third line starts with the icon of the limit the verdict speaks for. When both readings are on pace and in no danger, it says "both on pace", without an icon. There is no status bar glance: it only repeated the widget.
- Tried from a shell, in screenshots: every range, both weekly charts side by side and the switch when narrow, hidden names as the first build drew them (letters; every name in Burning now too), the dialog at 1100 × 680 and at 880 px wide, the sidebar widget with two rows. Not tried by hand when this was written: every hover (a ruler's segment and its chip, both charts, the bars, a project row, the calendar), every click (a ruler, the switch, the ranges, Hide names, refresh, a project row and its name, "N more", a Burning now row, the hover on an earlier week, the folding of Claude, Codex and a machine's containers (a machine's chevron is only seen in 30 days and All, which list a container; the shots were of 7 days) and its keeping across an open, the glances), the keys `1` to `4`, `r`, `h` and Escape, the rail, a dry or tight limit's ruler, a five-hour ruler, the year in two rows on screen (seen only moved to the top in a throwaway build), a real laptop window, and how the bars' rise looks.
