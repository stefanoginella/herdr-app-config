# `file-explorer`

Notes for agents on the mod in `mods/file-explorer/`. The index and what holds for every mod are in `AGENTS.override.md`.

The gallery calls this mod File Explorer, and the panel heading is Files.

A clone of Herdr's `files` panel (from version 0.1.18), without its preview (a click on a file opens it in `file-editor`), with file type icons, a dot on folders with git changes inside, a right-click menu (open in VS Code, Obsidian or TextEdit, reveal in Finder, new file and new folder, rename, duplicate, copy and paste through the clipboard, move to the Trash), drag to move or to paste a path in a terminal, files dropped from Finder, and undo.

## What is where

- `main.js`: the panel. `open()` asks the tab's editor for a file, and splits one in when the tab has none; `location()` keeps the folder shown while an editor has the focus. `refresh()` lists the folder, then reads what git ignores, which folders have changes inside (through `repoStatus()`) and Obsidian's vaults; `refreshIfDue()`, every 500 ms and on every draw, decides when; `watchRoot()` watches the folder shown; `shown()` finds the row of the file the tab's editor shows; `rows()` draws, highlights that row and carries the drag and drop handlers; `follow()` and `ended()` watch the window while an entry is pressed (`on_window_mouse_move`, `on_window_mouse_up`); `act()` runs a request and keeps how to take it back in `last`; `bring()` copies in files from outside (dropped from Finder, on the clipboard, or picked in the system's file picker); `moved()` / `gone()` keep the tree's open folders in step.
- `ops.js`: every file operation, and the request channel. Its header lists the requests. `MOVE`, `COPY` and `MAKE` are the three shell scripts every change to a file goes through; the clipboard is reached through `osascript`. A `pick` request is turned into copies by the panel, which opens the picker when it takes it: the menu's copy is gone by then.
- `menu.js`: the right-click menu. "Add Files…" (folders on this Mac only, like Copy and Paste) leaves a `pick` request for the folder clicked, the folder of the file clicked, or the folder shown. `naming.js`: the dialog that asks for a name, for a rename or a new file or folder. `confirm.js`: the Trash question. The mod opens itself for these, with `props().menu`, `props().naming` or `props().confirm`.
- `icons.js`: which icon a name gets. `icons/`: Material Icon Theme's SVGs and `map.js`, both written by `icons/build.py` from a release of that package (see its header). Never edit them by hand.
- State: a request waits in shared `file-explorer.request` only until the panel takes it. What undo takes back is in the panel's memory only. Nothing else is kept.
- Key command: `file-explorer.undo`, bound to `cmd-z` in the `global` section of `keys.json`.
- The header's lens runs `project-search.open`; a folder's "Find in Folder…" (menu.js) leaves `project-search.ask` first.

## Behavior to preserve

- A menu or a dialog never runs a program itself: its copy closes at once, and what it started is cancelled before it answers. It calls `ops.request()`, and the panel runs it. The same holds for `space-folders`' `open.js`.
- Nothing is overwritten. A rename or a move goes through the one `MOVE` script in `ops.js`, which refuses a name that exists (except a change of case of the same file). A copy goes through the one `COPY` script, which claims its name (`mkdir`, or a no-clobber create) before it copies: a duplicate takes the first free "copy" name, and a file from outside keeps its name or is refused. A new file or folder goes through the one `MAKE` script, which refuses a name that exists and creates with `mkdir` or a no-clobber create.
- The Trash, opening in an app, Finder and the clipboard are for files on this Mac (`ops.canOpen`, `ops.canTrash`, `ops.canShare`). On another machine the menu offers New File, New Folder, Rename and Duplicate only, and drag still moves.
- Undo is one step, of the last request that changed a file. A move or a rename goes back through `MOVE`, so it is refused when the old name has been taken. A trashed file comes back from the path `trash -v` printed. After a duplicate, a paste, a drop from Finder or a new file or folder there is nothing to undo, rather than something older: the record is cleared when a change begins, not when it ends. An undo is not itself undone. The key is global, so a stale record must find nothing: it is dropped when the panel shows another folder, and ignored after five minutes (`UNDO_FOR`).
- Files from Finder are copied, never moved.
- Pointer positions come in window pixels: multiply a length of the panel's by `settings().zoom` before comparing the two.
- Obsidian opens a folder only as a vault: a folder or a project gets "Open in Obsidian" only inside a registered vault. A Markdown, canvas or base file gets it anywhere.
- A drag is over the folder of the row under the pointer (a folder row: itself). It can't land where the entry already is, or inside itself.
- One press on a row begins two things: Herdr's file drag (`drag_paths`: the name that follows the pointer, and a path pasted where a terminal takes it) and this panel's own move, which lands on the release over a row or under the list. **A release must never be able to use a drag left behind.** While an entry is pressed, and only then, the panel's root watches the window (`on_window_mouse_move`, `on_window_mouse_up`); the press draws again so the next frame has them.
  - Every left release anywhere in the window ends the drag (`ended()`), one step after the release. Herdr runs window observers between GPUI's capture and bubble phases, so they come before the panel's own handlers of the same release. A row's or the tail's `on_mouse_up` (the drop or the click) and an `on_drop` (Finder, which runs before its element's `on_mouse_up` and stops the release) must still find the drag. Don't make `ended()` drop: it would run before `on_drop`, and a drag left behind plus a drop from Finder would become a move.
  - A window move with the left button not held ends a drag whose release was never seen (it went out of the window and ended there).
  - Every press that didn't begin the drag ends it too, in the panel (`on_mouse_down` on the root) or anywhere else in the window (`on_mouse_down_out`): a window can be pressed with no move seen first. Keep all of them.
- Every element with a left mouse-up handler also has its own `on_drop`: a drop from Finder is a mouse-up too, and only the element's own drop handler runs before it, and stops it.
- The git scan is Herdr's from 0.1.18 (`repoStatus()`): one scan of a repository at a time for every copy, reused for longer after a slow one (`watchAt`: five times what it took, at most a minute; `pollAt`: at least 10 s), and none while the window isn't active. The panel polls with `refreshIfDue()`, never with `refresh()` on a timer, and a folder watch only marks the context dirty (`dirtyAt`). Its scans are kept under this mod's own key, `file-explorer.repoStatus.v1`, never Herdr's `herdr.repoStatus.v2`: this scan lists what git ignores too (`--ignored=matching`), and sharing one key with Herdr's Files and Changes would mix the two kinds of answer.
- A refresh after this panel changed a file (`act()`, `bring()`) is `refresh(cx, true)`: urgent, and allowed while the window isn't active, so what the change did shows at once. One asked for while a load runs is not dropped: `again` runs one more load, forced if any of the asks was.
- The folder watch belongs to the context (`context.watch`) and is cancelled when another folder is shown: at most 64 folders can have a watch waiting. A watch that answers `[]` (cancelled) changes nothing. The folder watch is `watchRoot()`. A method defined twice in a class is silently replaced by the second: until 0.1.18's port the folder watch never ran for that reason, since the drag had a `watch()` too.
- `follow()` only decides what is drawn: outside the panel (from the window moves' real position) nothing is aimed at or faded, and over the header nothing is aimed at. The drag itself goes on, and may come back. It must never be what protects a file.
- The Trash is `/usr/bin/trash`, by its path: another `trash` on the `PATH` may read `-v` differently.
- Left-click: a folder folds, a file opens in the tab's editor. The panel never runs the editor: it leaves the file in shared `file-editor.open` and focuses the tab's `file-editor` pane, or splits one in with props `{ tab }` beside the focused pane. After a move or a rename it leaves `file-editor.moved`, so an open file goes on under its new name. A new file is opened the same way once it is made (`act()`), when the panel still shows the folder it was asked from; the folder it is in unfolds (`made()`).
- The row of the file the tab's editor shows is highlighted (`shown()`), whichever pane has the focus: the file's own row, or the topmost closed folder it is in. Nothing is highlighted for a file outside the folder shown or on another machine, or when the tab has no `file-editor` pane: an entry in `file-editor.shown` can outlive its editor (a crash), so the pane is looked for. The panel never unfolds or scrolls to that row.
- While a mod pane (the editor) has the focus the panel keeps the folder of the terminal that had it before, in that tab (`held` in `location()`): a mod pane is in no folder, and the tree must not jump to the space's folder when a file is clicked.

## The icons

- The icons in `mods/file-explorer/icons/` are a release of Material Icon Theme (MIT), named in `icons/map.js` and in `NOTICE`. To update them, follow the header of `icons/build.py`, then update the version in `NOTICE`.
